I see what you’re trying to ask — you’re asking “who defines / where does the routing table destination come from?”, not just how to calculate it.


Let’s clarify this cleanly.

🔹 Who creates the “Destination” in a routing table?


👉 Short answer:

The device itself (host or router) builds it based on its network configuration

🔹 There are 3 main ways a destination appears


1. ✅ Directly connected networks (MOST IMPORTANT)


When you configure an interface:

IP:   192.168.1.10
Mask: 255.255.255.0

👉 The system automatically creates:

Destination: 192.168.1.0/24

💡 You did NOT type this manually

👉 The OS/router calculates it

2. ✅ Static routes (you add them)


You can manually say:

“To reach 10.0.0.0/8 → go through this gateway”

👉 Then the routing table will contain:

Destination: 10.0.0.0/8

💡 Here, you define the destination

3. ✅ Default route


You often configure:

Gateway: 192.168.1.1

👉 This creates:

Destination: 0.0.0.0/0

💡 Meaning: “everything else”

🔹 Important mental model


Think like this:


👉 A routing table is just:


“For this NETWORK (destination), send packets THIS WAY”

🔹 Example (NetPractice style)


If a machine has:

IP: 192.168.1.10
Mask: 255.255.255.0
Gateway: 192.168.1.1

It will automatically have:

192.168.1.0/24 → direct (interface)
0.0.0.0/0      → 192.168.1.1

🔹 Now I guide you (important exercise)


Imagine:

IP:   10.5.23.7
Mask: 255.255.0.0

👉 Without jumping:

  • What network is this machine in?

  • What destination will be added automatically?

If you answer that correctly, you’ve basically understood half of routing tables — which is exactly what NetPractice expects.
