1️⃣ CIDR notation — what /27 REALLY means

You already know this subnet mask:

255.255.255.224

CIDR notation is just a shorter way to say the same thing.

⸻

🔹 Where does /27 come from?

Count the number of 1 bits in the subnet mask.

255 = 11111111  (8 bits)
255 = 11111111  (8 bits)
255 = 11111111  (8 bits)
224 = 11100000  (3 bits)

Total = 8 + 8 + 8 + 3 = 27

✅ So:

255.255.255.224  ==  /27


⸻

🔹 What does /27 tell you immediately?

As an experienced programmer, you should extract facts instantly:

Fact	Value
Total bits	32
Network bits	27
Host bits	5
IPs per subnet	2⁵ = 32
Usable hosts	30

So when you see:

192.168.82.222/27

You should instantly think:

“This subnet has blocks of 32 IPs.”

⸻

2️⃣ How routers decide if two IPs are in the same subnet

This part is pure bitwise logic — very C-like 💙

Routers do one operation only:

IP address
AND
Subnet mask

If the result is the same → same subnet

⸻

🔹 Example: are these two IPs together?

192.168.82.222/27
192.168.82.200/27

Step 1: last octet in binary

222 = 11011110
200 = 11001000
224 = 11100000   (mask)


⸻

Step 2: AND operation

222 AND 224
11011110
11100000
--------
11000000  = 192

200 AND 224
11001000
11100000
--------
11000000  = 192


⸻

Step 3: conclusion

Both results give:

192.168.82.192

✅ SAME subnet

⸻

🔹 What if one IP was .224?

224 = 11100000

224 AND 224
11100000
11100000
--------
11100000 = 224

Now the network is:

192.168.82.224

❌ DIFFERENT subnet

⸻

💡 Router logic (in pseudo-C)

if ((ip1 & mask) == (ip2 & mask))
    same_subnet();
else
    route_packet();

That’s it. No magic.

⸻

3️⃣ How this looks in real Linux networking

Now let’s connect theory → real commands 🧠💻

⸻

🔹 Assigning an IP with /27

ip addr add 192.168.82.222/27 dev eth0

Linux now knows:
	•	Network: 192.168.82.192
	•	Broadcast: 192.168.82.223
	•	Usable range: 193 → 222

⸻

🔹 Checking it

ip addr show eth0

You’ll see something like:

inet 192.168.82.222/27 brd 192.168.82.223

Linux calculated that automatically using the same logic you just learned.

⸻

🔹 Routing decision (very important)

Linux routing table:

ip route

You might see:

192.168.82.192/27 dev eth0 proto kernel scope link

Meaning:

“Anything destined for this subnet does NOT go to the router — send it directly.”

⸻

🔹 Ping behavior (this is gold 🥇)

If you do:

ping 192.168.82.210

✅ Direct ARP request (same subnet)

But:

ping 192.168.82.250

❌ Goes to default gateway (different subnet)

4️⃣ One last deep intuition (this is the real mastery)

❌ Wrong mental model

“224 is the max value”

✅ Correct mental model

“224 is a boundary marker”

Subnet masks slice the address space, they don’t limit numbers.

Just like array indexing:

int arr[32]; // indices 0..31

	•	32 is not usable
	•	It defines the next block

When you see /27:

	•	First IP → network
	•	Last IP → broadcast
	•	Everything else → usable
